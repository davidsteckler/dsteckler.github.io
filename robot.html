Quick command guide
  • forward(160) moves 160 units in the direction the turtle faces.
  • left(90) turns left a quarter turn. It does not move the turtle.
  • penup() lifts the pen so moving leaves no line. pendown() draws again.
  • goto(-40, 20) moves to an exact spot: x first, then y. Negative x goes left of center; positive y goes above center. It keeps the same facing direction.
  • circle(12) draws a circle with a radius of 12. When facing right, the turtle starts at the bottom of the circle.
  • color("blue") sets the pen color. Color names need quotes.
  • pensize(5) sets the line thickness.
Stuck? Try this debugging routine
  1. Read the error. Find the line number in your editor.
  2. Check spelling and lowercase letters: forward, not Forward.
  3. Match every opening ( with a closing ). Put a comma between x and y in goto(x, y).
  4. If a stray line connects two shapes, check for penup() before you move.
  5. If something is missing, check for pendown() before you draw.
  6. Fix one thing. Run the whole program again from a fresh start. Compare.

Still stuck? Show a partner the first place your drawing differs from the preview, then ask your teacher.

Finished early? Turn four sides into a loop

In step 2, replace the eight alternating forward / left lines with this block. Keep the pen movement and color lines above it.

for side in range(4):
    forward(160)
    left(90)

The colon starts the loop block. Indent both lines underneath with four spaces. Python repeats those two indented lines four times. Predict what happens if you use range(3), then test it.

Teacher notes · pacing & sharing

Goal: Students will create a drawing using a sequence of Turtle commands and explain how lifting the pen changes the output.

Pacing: Move through the steps as students are ready. Pause to compare drawings and resolve errors. Save unfinished programs to continue next class.

Open a blank CodeHS Python Turtle sandbox or a local Python editor with Turtle support. Students type each new block into their editor. Ask them to predict what it will draw, run it, and explain what changed. Demonstrate one command at a time when students need support.

Partner share: “My robot is called ___. I changed ___ by editing ___. One thing I fixed was ___.” Each partner points to a command in their own code.

Evidence: Have students save their program and submit a screenshot of the drawing through your usual class assignment. The exit ticket is in step 6. This page does not collect student work.
